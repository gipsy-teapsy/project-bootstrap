# Project Bootstrap — быстрый старт

**Версия:** 0.1.8 · **Разработчик:** Gipsy · **Статус:** бета

## 1. Что такое Project Bootstrap и где начать

Project Bootstrap помогает организовать работу над проектом с помощью ChatGPT и Codex: уточнить цель, принять важные решения, выполнить задачи и проверить результат. В долгой работе он сохраняет нужные решения и состояние, чтобы после паузы или смены чата не приходилось начинать заново.

Вам достаточно описывать желаемое обычными словами. Система сама выбирает подходящую роль, использует доступные материалы и задаёт вопросы, которые действительно влияют на следующий шаг.

- **ChatGPT** удобен для обсуждения идеи, принятия решений и объяснения результатов.
- **Codex** нужен, когда требуется читать или менять реальные файлы, проверять Git, запускать команды и тесты, работать с другими доступными рабочими ресурсами.

Можно начать сразу в Codex. Если обсуждения достаточно, можно оставаться в ChatGPT; переход понадобится, когда следующему шагу нужен доступ к реальному проекту.

## 2. Подключение и первое сообщение

### 2.1. Обычный чат ChatGPT

Подходит для одного разговора или пробного запуска.

1. Скачайте [CHATGPT_CLOUD_MANAGER.md](CHATGPT_CLOUD_MANAGER.md). В этом файле уже собраны нужные инструкции Project Bootstrap.
2. Откройте новый чат ChatGPT и прикрепите файл.
3. Отправьте первое сообщение, например:

> Используй прикреплённый CHATGPT_CLOUD_MANAGER.md как инструкции Project Bootstrap. Общайся со мной по-русски. Хочу создать сайт для записи клиентов: помоги понять, с чего начать.

Отдельный проект ChatGPT и его настройки инструкций для этого варианта не нужны.

### 2.2. ChatGPT Project

Этот вариант удобен для долгой работы в нескольких чатах одного проекта.

1. Создайте проект в ChatGPT.
2. Скачайте [CHATGPT_CLOUD_MANAGER.md](CHATGPT_CLOUD_MANAGER.md) и добавьте его в источники проекта.
3. Откройте настройки инструкций проекта — **Project Instructions** — и вставьте готовый блок ниже.
4. Откройте чат внутри проекта и опишите, что хотите сделать:

> Хочу создать приложение для семейных расходов. Помоги уточнить цель и организовать работу.

#### Готовый блок Project Instructions

Скопируйте этот блок в Project Instructions вашего ChatGPT Project:

```text
Use the uploaded CHATGPT_CLOUD_MANAGER.md as the Project Bootstrap Manager contract for this Project.
Follow its canonical Manager, Shared Core, and Cloud delivery sections.
Keep every user-visible explanation, question, review, summary, and result interpretation in the user's current language.
English canonical source text and agent-facing prompts must not switch the surrounding user-facing response to English.
Use English by default only for agent-facing material where appropriate.
Do not invent mutable workspace facts; route bounded workspace inspection or execution to Codex when evidence is required.
```

Это инструкция помощнику; её английский текст не должен менять язык общения с вами. Весь большой `CHATGPT_CLOUD_MANAGER.md` в поле инструкций копировать не нужно: он добавляется отдельным файлом в источники проекта. Остальные исходные инструкции загружать не требуется.

При обычном обновлении замените файл новой опубликованной версией. Если короткая инструкция не изменилась, повторно вставлять её не нужно. Как проекты объединяют файлы и инструкции, объясняет [справка ChatGPT](https://learn.chatgpt.com/docs/projects?surface=app).

### 2.3. Codex

Если Project Bootstrap уже установлен, начинайте с шага 3. Шаги 1–2 относятся к установке плагина из его публичного репозитория; в шаге 3 откройте папку своего проекта, над которым будете работать.

1. Добавьте источник плагина одним из двух способов:
   - **Локальная копия.** Откройте [репозиторий Project Bootstrap на GitHub](https://github.com/gipsy-teapsy/project-bootstrap), выберите **Code → Download ZIP** и распакуйте архив. Откройте распакованную папку репозитория как проект в приложении Codex и полностью перезапустите приложение. В корне этой папки уже находится каталог плагинов.
   - **Источник через Codex CLI.** Если установлен Codex CLI — консольная программа `codex` — выполните команду в обычном терминале. Она добавит источник из GitHub; скачивать и открывать архив для этого способа не нужно:

```text
codex plugin marketplace add https://github.com/gipsy-teapsy/project-bootstrap --ref main
```

2. В каталоге плагинов приложения выберите источник **Project Bootstrap** и установите плагин **Project Bootstrap**. Оставьте включёнными Manager, Master и Task. Отображаемое название источника — Project Bootstrap; его техническое имя для команд CLI — `gipsy-project-bootstrap`. Добавление источника и установка плагина — два отдельных шага; см. [официальную инструкцию OpenAI](https://developers.openai.com/plugins/build/plugins).
3. Откройте рабочую папку в Codex и начните новый чат. Для существующего проекта это его текущая папка. Если проекта ещё нет, создайте или выберите пустую папку для будущей работы и откройте её; заранее придумывать структуру файлов не требуется.
4. Опишите цель. Для существующего проекта, например:

> Подключи Project Bootstrap к этому проекту. Сначала разберись в текущих файлах, затем помоги организовать дальнейшую работу.

Для нового проекта:

> Хочу сделать сайт для записи клиентов. Помоги уточнить цель и начать проект в этой папке.

Если установка ограничена правилами организации, может понадобиться помощь администратора. Для установки через GitHub в рабочем пространстве ChatGPT есть [отдельная инструкция](https://github.com/gipsy-teapsy/project-bootstrap/blob/main/docs/MARKETPLACE_INSTALL_RU.md).

## 3. Как будет устроена работа

### 3.1. Manager, Master и Task

Внутри Project Bootstrap есть три роли:

- **Manager** помогает настроить общую работу: понять цель, важные решения и нужные рабочие среды.
- **Master** координирует работу в проекте: сверяет состояние, определяет следующие задачи и проверяет результаты.
- **Task** выполняет отдельную конкретную работу — например, исследование или исправление ошибки.

Обычно роли выбираются автоматически по смыслу запроса. Маленькую задачу координатор может выполнить сам; отдельные исполнители, планы, чаты и ветки Git нужны только когда помогают работе. Git необязателен.

Один чат не является самим проектом. Для долгой работы важное состояние сохраняется в согласованном месте, чтобы новый чат мог продолжить её. После обрыва во время изменения файлов система сначала проверяет, что реально успело измениться.

Наличие инструмента не означает разрешения на любое действие. Разрешение менять файлы не даёт автоматически права отправлять их в GitHub или публиковать сайт. Можно выбрать, сколько решений обсуждать с вами: **Совместно**, **По ключевым решениям** или **Делегированно**. Это меняет участие в работе, но не технические права.

### 3.2. Переход из ChatGPT в Codex

Когда потребуются реальные файлы или команды, Project Bootstrap подготовит сообщение для Codex. Откройте там нужную папку проекта и отправьте сообщение целиком. Если продолжаете обсуждение в ChatGPT, верните туда отчёт Codex.

Согласованные цель, ограничения и разрешения должны сохраниться при переходе. Например:

> Только выясни, почему падает тест X. Ничего не меняй.

Codex может найти переименованный файл и проверить его, если это та же согласованная работа. Но «только проверить» не превращается в «проверить и исправить». Если конкретный следующий шаг ещё не выбран, сначала проверяется состояние проекта, затем определяется подходящая работа.

Если плагин установлен в Codex, сообщение использует его компоненты. Если нет, Project Bootstrap подготовит сообщение для конкретной проверки или задачи без обязательной установки всего плагина.

## 4. Что происходит после первого запроса

### 4.1. Новый проект

Описываете идею → уточняете важные решения → когда нужны реальные файлы, работа переходит в Codex → дальше продолжаете обычными запросами.

Например, на «Хочу сделать сайт для записи клиентов» Project Bootstrap сначала уточнит один важный вопрос: «Кто будет записывать клиентов — они сами или администратор?» База данных и программная платформа выбираются позже, когда понятен нужный результат первого этапа.

### 4.2. Существующий проект

Просите разобраться в текущем состоянии → система читает доступные материалы → проверяемые факты не приходится вспоминать вручную → определяется или выполняется следующий шаг.

### 4.3. Примеры следующих запросов

Можно писать:

- «Создадим новый проект».
- «Продолжим вчерашнюю работу».
- «Есть баг: после сохранения форма сбрасывается. Разберись и исправь».
- «Нужно добавить возможность отменять запись».
- «Работа оборвалась во время изменений. Проверь, что реально успело измениться».
- «Проверь, всё ли готово по исходной задаче».

Project Bootstrap проверяет и то, что результат работает, и то, что исходная задача выполнена целиком. Он не должен угадывать состояние недоступных файлов или серверов. Объяснения остаются на вашем языке, даже если сообщение для другого помощника написано по-английски.

Подробнее о ролях, разрешениях, сохранении состояния, проверках и работе на нескольких компьютерах — в [руководстве пользователя](USER_GUIDE_RU.md).
